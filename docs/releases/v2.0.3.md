# BenchMax v2.0.3

A connectivity and polish release: BenchMax now speaks the Model Context Protocol, shows its own update notifications, and lets you set defaults for every run. Fresh installs no longer crash on first launch.

## AI tools can talk to BenchMax

BenchMax now speaks the Model Context Protocol (MCP), so tools like Claude, OpenCode, Cursor, and VS Code can list benchmarks, start runs, and read results directly. One command installs it:

```
py cli.py install-mcp --client claude
```

The Settings tab shows live MCP status with copy-paste config snippets for each app. If you prefer the terminal, `py cli.py update-check` checks for new releases too.

## Set once, run everywhere

A new Settings tab (gear icon in the sidebar) holds run defaults: temperature, max tokens, system prompt, quick-test toggle, loop detection, and NIAHS context length. Every new run starts with these values. You can also set a default provider URL, adjust how often the UI refreshes, and toggle the update checker.

## Never miss an update

BenchMax checks GitHub for new releases once a day. When a newer version exists, a small banner appears with a Download button and a link to the release notes. You can turn this off in Settings or run `py cli.py update-check` to check manually.

## Runs started elsewhere now show up

Benchmarks started from the CLI or MCP now appear live in the Run tab. No more refreshing to see if something is running.

## Fixes

- Fresh installs no longer crash on startup — the app now creates its data folder before opening the database, instead of failing on PCs that never ran BenchMax.
- Docker container timeouts now explain when the engine itself is stuck — if Docker Desktop is hung on "Starting the Docker Engine," the error message names the problem and tells you how to verify it.

## Other changes

- Live run stats (accuracy, speed, token totals) now update with every sample instead of lagging behind.
- Dead code paths removed — old Windows-native sandbox layers and the portable-runtimes installer are gone. All code benchmarks still run in Docker, exactly as before.
- Test suite expanded to 469 backend and 43 frontend tests.
