# BenchMax v2.0.2

A safety and polish release: password-protected network sharing, a download half the size, and snappier run controls. Nothing to reinstall, no migration steps.

## Share safely on your network

Serving BenchMax on your local network now shows visitors a login screen that can't be skipped. You set the password once on the server machine; your own browser on that machine keeps working with no login. Forgot it? Deleting one file resets it (see the setup guide).

Two quiet privacy fixes ride along:

- The server now listens on your own PC only by default. Sharing on the network is still one flag away, with a reminder to set the password first.
- Cloud provider keys are no longer saved in the results database. They travel in memory only, so a shared or backed-up database can't leak them.

## Download half the size

The Windows download is now roughly 170 MB instead of roughly 380 MB. Unused machine-learning libraries were stripped from the build after proving no benchmark uses them. All benchmarks run exactly as before.

Release builds also install from a pinned dependency list now, so every release builds identical libraries instead of whatever is newest that day.

## Smoother running

- Starting a 5th simultaneous benchmark now tells you the machine is busy and points at the saved waiting run, instead of starving everything at once.
- Pause and halt respond within about 5 seconds even on slow long-context runs (previously checked far less often).
- Two agentic runs at the same time no longer overwrite each other's live Turn N/M display.
- The command-line tool covers every server feature now, including exporting hand-picked runs.

## Fixes

- The Run tab no longer starts a hidden benchmark: clicking a category or typing a search moves the dropdown to the first visible entry, so Start always runs what is shown.
- Empty exports now say there is nothing to export instead of downloading a misleading file.
- Missing-run errors name the run, and wrong-state actions (e.g. pausing a finished run) report cleanly, so scripts and the CLI can tell which ID failed.
- Reference site corrected: API and command counts, host-local numbers, the LiveBench half-Docker marking, and the two missing benchmark pages are all accurate again.
